# VAL3 应用架构与编码约定

> 依据：本机现存的 3 套真实工程（`usrapp_dr`、`Paoguang`、`ValSolar_SP2`）的实际写法归纳，不是教科书。

**应用位置**：cell 内 `D:\6_SRSFiles\DeepSeek_AI_work1\Controller1\usr\usrapp\NewApp`（SRC 8.15.3 / TX2-90L）。
源码在工作区 `staubli\app\NewApp`，用 `tools\deploy.ps1` 单向同步到 cell。

## 1. 文件四件套

| 扩展名 | 作用 | 要点 |
|---|---|---|
| `.pjx` | **项目**（一个模块） | 声明 `Parameters version=`（目标 SRC）、`stackSize`、程序清单、数据文件、库引用 |
| `.pgx` | **程序**（一个 function/procedure） | XML 外壳 + `<Code><![CDATA[ ... VAL3 ... ]]></Code>` |
| `.dtx` | **数据**（全局变量/类型） | `<Data name type size access>`，可带初值 `<Value>` |
| `.ltx` | 编译产物（导出符号表） | **不要手写**，编译时由 SRS 生成 |

一个**应用** = `usr/usrapp/<应用名>/` 下的一个文件夹，里面可直接放一套 `.pjx/.pgx/.dtx`（如 `Paoguang/Paoguang.pjx`）。

## 2. 路径与引用

- 库引用写法：`<Library alias="io" path="Disk://io/io.pjx" />`
- **`Disk://` 相对于 `usr/usrapp/`**，不是相对于当前应用目录。所以 `Disk://saveData/saveData.pjx` = `usr/usrapp/saveData/`。
- 代码里用 `alias:符号` 访问：`io:aOutput[0]`、`rs:bIsScara`、`cfg:nConfigs[5]`、`call io:setAnaOutput(...)`。

## 3. 任务模型（本骨架采用）

```
start()                 ← 应用入口
 ├─ call init()
 ├─ taskCreate "stateMachine", 50, stateMachine()   // 高优先级：工艺/状态
 ├─ taskCreate "taskManager", 20, taskManager()     // 低优先级：守护
 └─ do delay(1) until false                         // 心跳，不退出
```

- `taskCreate "<名字>", 优先级, 程序()`；名字是字符串，守护时用 `taskStatus("名字")` / `taskResume("名字",1)`。
- 循环里必须 `delay(0)` 让出 CPU，否则会把控制器/仿真器跑满。
- 守护任务：`taskStatus(...) != 1` → `taskResume(...,1)`，间隔 5s，防止通信中断把任务挂死。

## 4. 状态机约定

| 值 | 状态 | 进入动作 | 退出条件 |
|---|---|---|---|
| 0 | 初始化 | `call init()` | 立即 → 10 |
| 10 | 空闲 | `bRunning=false` | `bStartCmd` 置位 → 20 |
| 20 | 运行 | 调工艺程序、`nCycleCount+1` | `bPauseCmd` → 30；`bStopCmd` → 10 |
| 30 | 暂停 | `bRunning=false`，保持位置 | `bStartCmd` → 20；`bStopCmd` → 10 |
| 90 | 故障 | `bRunning=false` | `bResetCmd` 清报警 → 10 |

- 指令位（`bStartCmd` 等）由 HMI/PLC 置 true，**状态机消费后负责复位**，避免重复触发。
- 报警用 `nAlarm`（代码）+ `sAlarmMsg`（文本），HMI 只读。

## 5. 命名（沿用你现有工程的习惯）

| 前缀 | 含义 | 例 |
|---|---|---|
| `b` / `n` / `s` | 全局 bool / num / string | `bRunning` `nCycleCount` `sAlarmMsg` |
| `l_` | 局部变量 | `l_nIndex` `l_bErr` |
| `x_` | 参数 | `x_sType` `x_nStep` |
| `a` | 数组/模拟量 | `aOutput` `aInput` |
| 大写开头 | 程序名/任务名 | `PLC` `HMI` `taskManager` |

## 6. `.pgx` 骨架（照抄即可）

```xml
<?xml version="1.0" encoding="utf-8" ?>
<Programs xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
          xmlns="http://www.staubli.com/robotics/VAL3/Program/2" >
  <Program name="myProg" access="private" >
    <Parameters xmlns="http://www.staubli.com/robotics/VAL3/Param/1" >
      <Parameter name="x_nStep" type="num" use="reference" xsi:type="element" dimensions="1" />
    </Parameters>
    <Locals>
      <Local name="l_nI" type="num" xsi:type="array" size="1" />
    </Locals>
    <Code><![CDATA[begin
  //VAL3 代码
end]]></Code>
  </Program>
</Programs>
```

- `use="value"` → 值传递；`use="reference"` → 引用（`.ltx` 里显示为 `&`）。
- 数组参数写 `dimensions="1"`；多维局部变量用 `size="3 3"`。

## 7. 待补模块（按需长出来）

| 模块 | 内容 | 依赖 |
|---|---|---|
| `Io/` | IO 抽象层（`getDio/setDio/getAnaIO` 封装、点位映射） | 现场 IO 表 |
| `Motion/` | 回零、点位运动、速度/加速度、`setPayload` | 坐标系、工具 |
| `Plc/` | PLC 握手（PROFINET/EtherCAT 或 socket） | PLC 型号/协议 |
| `Hmi/` | 页面、按钮回调（`_clickXxx`）、报警列表 | 页面需求 |
| `Recipe/` | 配方/产品参数（`.dtx` 里存表） | 产品字段 |

## 8. 规则（避免踩坑）

1. 新代码只用到目标 SRC 已有的指令；升级后靠 `Parameters version` 一行切换。
2. 每个 `taskCreate` 的循环必须有 `delay`。
3. 改 `.dtx` 变量名要全局搜 `.pgx` 里的引用，VAL3 不做重命名。
4. 手改 `.pjx` 后必须保证 `Programs` 里列出的 `.pgx` 都存在，否则编译直接失败。
5. 不要手写 `.ltx`；它由编译生成，提交时忽略。
