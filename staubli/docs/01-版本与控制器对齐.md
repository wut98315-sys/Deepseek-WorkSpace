# 版本与控制器对齐（更正版）

## 先更正一个错误判断

我上一轮说"本机 SRS 2019 最高只到 8.12、必须升级"——**这是错的**。依据是 `%APPDATA%\Staubli\SRS\2019.8\RobotInfo.json` 里的 `SrcVersions` 缓存，那只是 VAL3 源码模板缓存，不是控制器版本能力。

实测证据（2026-11-07 16:11 你新建的 cell）：

```
D:\6_SRSFiles\DeepSeek_AI_work1\Controller1\Controller1.controller
  <Version>s8.15.3Cs9_BS3337</Version>
  RobotSkin: TX2_90L-HB-L-WS

...\usr\configs\val3version.xml
  <Version name="val3" compatibility="11">s8.15.3cs9_BS3337</Version>
```

**结论：SRS 2019.8.1 能建 8.15.3 的 CS9 仿真控制器，8.15 不需要升级 SRS，也不需要再等安装包。** 骨架的 `.pjx` 已按 `s8.15.3Cs9_BS3337` 对齐。

## 但真机还有一段距离

| 对象 | 实际版本 | 影响 |
|---|---|---|
| 现场 TX2-90L 控制器 | **8.12.1**（备份 `val3version.xml`） | 不能直接跑 8.15 编译出的代码 |
| 另一台控制器 F17_5AEXD1_C_01 | **7.11.2** | 同上 |
| 你的仿真 cell | 8.15.3 | 仿真验证用 |

VAL3 的兼容规则是**控制器 SRC ≥ 程序声明的 SRC**（低版本控制器不能运行高版本编译的代码）。所以有两条路：

**路线 1（推荐，零风险）**：仿真用 8.15.3，**上真机前把 `.pjx` 的 `Parameters version` 改成 `s8.12Cs9_BS2378` 重新编译**。代码里只要不用 8.13–8.15 新增的指令，就能直接跑在 8.12 控制器上。

**路线 2**：把现场控制器刷到 8.15。需要 Stäubli 提供 CS9 的 SRC 升级介质 + 升级授权 + 回退方案。**不建议**只为了写应用去刷控制器。

## 如果确实要升级控制器，向供应商要这些

1. CS9 控制器从 8.12.1 → 8.15.3 的**升级介质**与操作手册
2. **升级授权**（是否包含在当前 license 内）
3. **回退方案**与风险说明（升级失败如何恢复）
4. 升级后对现有 `Paoguang` / `ValSolar_SP2` 应用的影响评估

## 日常注意

- 一个 cell 对应一个 SRC 版本，不要混编；多台设备就建多个 cell。
- 改 `.pjx` 的 `version` 字段 = 切换目标 SRC，这是唯一的版本开关。
- SRS 打开低版本工程时会提示"升级项目"，**升级后不可回退**，操作前先备份 cell。
