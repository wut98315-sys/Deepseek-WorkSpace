# IO 绑定：变量 → VirtualBoard0 物理通道

## 结论先说

`io.dtx` 里每个通道的 `link="..."` 是 **SRS 生成的 GUID**，不能手写（写错了控制器解析不了，也不会有任何报错，只会读到 0）。所以绑定**必须在 SRS 里点一次导入**，不是改文件能完成的。

已核实：

```
io.dtx:      dInput[64]  dOutput[64]  aInput[16]  aOutput[16]
VirtualBoard0: DInputs 64  DOutputs 64  AInputs 16  AOutputs 16
```

**数量完全一致，映射关系就是下标 1:1**：

| VAL3 变量 | 物理通道 |
|---|---|
| `dInput[0..63]` | VirtualBoard0 → DInputs channel 0..63 |
| `dOutput[0..63]` | VirtualBoard0 → DOutputs channel 0..63 |
| `aInput[0..15]` | VirtualBoard0 → AInputs：ch 64, 80, 96, 112, 128, 144, 160, 176（16 位有符号）+ ch 192, 224, 256, 288, 320, 352, 384, 416（32 位浮点） |
| `aOutput[0..15]` | VirtualBoard0 → AOutputs：通道号同上 |

## 官方一键导入（SRS 手册 8.8.1，第 48 页）

> "It is possible to import physical I/Os into an application by using the I/Os menu in the IMPORT contextual ribbon. This is used to automatically declare VAL3 variables linked to the PHYSICAL IOs selected."

操作：

1. 先**打开 io 应用**（导入的目标是"当前打开的应用程序"）
2. 选中控制器 → 打开 **HOME → PHYSICAL I/Os**（或在 CELL EXPLORER 里右键控制器 → PHYSICAL IOs）
3. 展开 `VirtualBoard0`，**全选**要导入的通道（DInputs / DOutputs / AInputs / AOutputs 各一组）
4. 在 **IMPORT** 上下文选项卡里点 **I/Os**
5. 命名方式选 **"previous library format (compatibility with 6.x versions)"**
   —— 这个选项生成的就是 6.x 那种整组数组（`dInput` / `dOutput` / `aInput` / `aOutput`），和你现在建的名字一致
6. 保存（SAVE ALL）

导入完，SRS 会把 `link="GUID"` 写进 `io.dtx`，每个通道一条。

> 如果 SRS 提示变量已存在/重名：说明现在手工建的这 4 个变量挡住了导入。先在数据编辑器里删掉这 4 个变量再导入（原文件已备份为 `io.dtx.bak_before_link`）。


正常应输出：

```
Name    Type Size Bound Missing Pct Dup
dInput  dio    64    64       0 100   0
dOutput dio    64    64       0 100   0
aInput  aio    16    16       0 100   0
aOutput aio    16    16       0 100   0
...
全部已绑定，无重复。
```

`Missing > 0` = 有通道没绑上；`Dup > 0` = 同一个物理通道被绑到多个变量（这种情况写输出会互相打架）。

## 为什么不能手写 GUID

- GUID 是 SRS 在导入时随机生成的（每台 cell 各不相同），不是由"板名+通道号"推导出来的
- cell 里没有任何文件保存 GUID ↔ 通道 的对照表（`virtualIOBoards.cfx` 只有通道号和描述）
- 手写一个看起来合法的 GUID，最坏情况是"编译通过、运行读到 0"，比报错更难查

所以正确做法只有两条：**SRS 导入**（推荐，一次 160 点），或**在 PHYSICAL I/Os 面板里逐点绑定**（160 次点击，不推荐）。

## 模板文件

- `usr\configs\templates\iomap\iomap.cfx` —— 系统信号（上电/模式/倍率/刹车）的映射表，和变量绑定是两回事，别混。它允许把 `enablePower`、`monitorSpeed` 等系统功能绑到物理通道上（远程控制用）。
- `usr\configs\virtualIOBoards.cfx` —— 虚拟板定义（通道数、16/32 位、有符号/浮点）
